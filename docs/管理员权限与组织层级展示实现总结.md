# 管理员权限与组织层级展示实现总结

本文档汇总：**操作级权限收口**、**管理员从飞书同步人员添加项目经理 / 团队负责人**、**管理员页团队 / 项目维度人员展示**，以及**「我的工作项」与团队负责人收件箱的树形层级展示**。便于评审、联调与后续扩展。

## 一、操作级权限配置：仅管理员

### 1.1 目标

- **项目经理**、**团队负责人**不再在「成员」「我的团队」等入口看到或配置「操作级权限」面板。
- 该类配置统一由**平台管理员**在「管理员 → 用户管理」等场景完成。

### 1.2 实现要点

- 默认矩阵 `lib/permissions.ts` 中 `managePermissions` 对 `projectManager`、`teamLead` 置为 `false`。
- `lib/services/permission-workflow.ts`：`listPermissionOverrides` 对非管理员返回空列表；`upsert` / `delete` 仅允许管理员通过校验。
- UI：项目 `app/projects/[identifier]/members/page.tsx` 仅在 `currentUser.role === "admin"` 时渲染 `PermissionOverridesPanel`。
- `app/(global)/team/page.tsx` 移除团队侧的 `PermissionOverridesPanel`。
- `app/(global)/admin/users/page.tsx`：`PermissionOverridesPanel` 与 `UsersTable` 的编辑能力仅在 `admin` 时开启。

### 1.3 与既有设计文档的关系

细则仍以 `docs/权限与菜单设计方案.md` 及 `lib/permissions.ts` 为准；本实现将**操作级权限**的**配置面**明确收敛到管理员角色。

## 二、管理员：从飞书同步表添加项目经理 / 团队负责人

### 2.1 数据来源

- Prisma 模型 `ExternalPerson`（及种子/同步写入的 `externalId`、`personId` 等）作为**飞书同步人员**来源。
- 若外部人员尚未关联 `Person`，保存时会创建 `Person` 并回写 `externalPerson.personId`。

### 2.2 业务行为

- **添加项目经理**：选择飞书人员 + 项目 → 创建或更新对应 `User` 为 `projectManager`，并对该项目 `ProjectMembership` 做 `upsert`（`isLead: true`）。
- **添加团队负责人**：选择飞书人员 + 团队 → 更新 `Team.leadId`，并确保该人员在 `TeamMembership` 中（`upsert`），`manualOverride` 标记为 true。

### 2.3 主要文件

| 类型 | 路径 |
|------|------|
| 工作流 | `lib/services/admin-role-workflow.ts`（`listExternalRoleCandidates`、`assignLeadershipFromExternalPerson`） |
| API | `app/api/admin/role-assignments/route.ts`（`POST`） |
| 管理端 UI | `components/admin/LeadershipAssignmentPanel.tsx`，挂载于 `app/(global)/admin/page.tsx` |

### 2.4 权限与安全

- API 与业务层要求调用方为 **admin**，非管理员返回 403。
- 不涉及飞书 OpenAPI 调用；依赖库内已同步的 `ExternalPerson` 数据。

## 三、管理员页：团队 / 项目两个维度的组织与人员展示

### 3.1 团队侧

- 在 `app/(global)/admin/page.tsx` 中以「团队侧组织架构」模块展示：团队名称、负责人、成员摘要、飞书 / 手动来源标记。
- 深链：`/admin/teams`（团队树与成员维护仍由既有 `TeamsTree` 等承担）。

### 3.2 项目侧

- 同页「项目维度组织人员」：按项目层级缩进列出项目，展示部分成员与负责人标记，并提供进入 `/projects/{identifier}/members` 的入口以查看**该项目下组织人员信息**。

### 3.3 角色权限矩阵表

- `admin/page.tsx` 中矩阵表增加 **团队负责人** 列，与 `permissionMatrix` 中的 `teamLead` 字段对齐，避免与仅三列的旧表不一致。

### 3.4 导航补强

- 管理员页头部增加「用户与角色」「团队组织」快捷链至 `/admin/users`、`/admin/teams`。

## 四、工作项列表：父任务 + 缩进子任务

### 4.1 「我的工作项」(`MyWorkbenchTable`)

- 依据 `WorkPackage.parentId` 在 `allWorkPackages` 内展开**父链**与**子孙**，表格行按树前序输出。
- 「主题」列通过 `paddingLeft` 与 `↳` 表达层级；根行字重略强于子行。
- 根任务集合的排序仍贴近原「我的工作」列表顺序（优先使用用户可见子集在 `workPackages` 中的顺序，未见于子集时再按全量列表索引）。

**文件**：`components/work-packages/MyWorkbenchTable.tsx`。

### 4.2 团队负责人收件箱 (`MyTeamWorkInbox`)

- 待核对 / 已驳回列表同样按 `parentId` 扁平化为带 `level` 的行，卡片 `marginLeft` 与标题前缀 `↳` 表示子任务。
- 详情链接：有 `projectId` 时用 `project.identifier` 拼 `/projects/{identifier}/work-packages/{id}`；无项目时用 `/work-packages?focus={id}`。
- 传入 `projects` 由 `app/(global)/team/page.tsx` 提供。

**文件**：`components/team-lead/MyTeamWorkInbox.tsx`、`app/(global)/team/page.tsx`。
