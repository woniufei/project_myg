# 权限与菜单设计方案（四级角色 + 三级层级）

> 基于用户确认后的最终方案：需求项采用独立关联表（支持多条），团队模型自建 + 预留飞书同步扩展，项目节点用 parentId 区分，创建工作项时需求项必填（Admin/PM/TeamLead）。

---

## 一、根因分析

| 编号 | 根因 | 关键证据 |
|------|------|---------|
| 根因1 | 角色体系缺 `teamLead` | `PlatformRole` 仅 `admin / projectManager / participant` |
| 根因2 | 项目创建权限粒度不足 | `manageProjects` 同时控制父项目/子项目创建 |
| 根因3 | 缺少团队/组织架构模型 | Prisma schema 无 `Team`/`TeamMembership` 表 |
| 根因4 | WorkPackage 缺少需求项关联 | `WorkPackage` 模型无需求项相关字段/关联表 |
| 根因5 | 菜单渲染缺少角色级控制 | 代码中未见基于角色的菜单过滤逻辑 |

## 二、数据模型变更（Prisma）

### 2.1 PlatformRole 扩展

```prisma
enum PlatformRole {
  ADMIN
  PROJECT_MANAGER
  TEAM_LEAD      // 新增
  PARTICIPANT
}
```

### 2.2 新增 Team / TeamMembership 模型

```prisma
model Team {
  id          String          @id @default(cuid())
  name        String
  description String?
  leadId      String?         // 团队负责人对应的 User.id
  memberships TeamMembership[]
  createdAt   DateTime        @default(now())
  updatedAt   DateTime        @updatedAt
}

model TeamMembership {
  id       String @id @default(cuid())
  teamId   String
  personId String
  team     Team   @relation(fields: [teamId], references: [id], onDelete: Cascade)
  
  @@unique([teamId, personId])
  @@index([teamId])
  @@index([personId])
}
```

### 2.3 WorkPackage 新增需求项关联表（支持多条）

```prisma
model WorkPackageRequirement {
  id            String      @id @default(cuid())
  workPackageId Int
  content       String      // 需求项内容
  sortOrder     Int         @default(0)  // 排序
  createdAt     DateTime    @default(now())
  workPackage   WorkPackage @relation(fields: [workPackageId], references: [id], onDelete: Cascade)
  
  @@index([workPackageId])
  @@index([workPackageId, sortOrder])
}
```

WorkPackage 模型增加反向关系：
```prisma
model WorkPackage {
  // ... 现有字段 ...
  requirements WorkPackageRequirement[]  // 新增反向关系
}
```

// Participant: 看参与的项目 + 仅本人负责/创建的工作项（现有逻辑）

if (user.role === "teamLead") {

## 五、项目创建校验规则

| 角色 | 能否创建项目节点（parentId=null） | 能否创建项目（parentId≠null） | parentId 必填约束 |
|------|:------------------------------:|:---------------------------:|:----------------:|
| Admin | ✅ | ✅ | 否 |
| PM | ✅ | ✅ | 否 |
| TeamLead | ❌ | ✅ | **是**（只能创建子项目） |
| Participant | ❌ | ❌ | — |

## 六、工作项需求项规则

| 角色 | 创建工作项时需求项必填？ | 说明 |
|------|:---------------------:|------|
| Admin | **是**（至少1条） | 管理员也必须填写 |
| PM | **是**（至少1条） | 项目经理也必须填写 |
| TeamLead | **是**（至少1条） | 团队负责人也必须填写 |
| Participant | 否 | 普通员工可选填 |

> 后端校验逻辑：创建/更新工作项时，若用户角色为 admin/projectManager/teamLead，则检查 `requirements` 数组长度 ≥ 1，否则返回 400 错误。
