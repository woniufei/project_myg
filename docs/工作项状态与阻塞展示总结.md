# 工作项状态与阻塞展示总结

本文档汇总当前平台对**工作项主状态**、**阻塞/延期派生标签**、**权限与自动化规则**及**「我的工作」列表**相关实现，便于评审取舍与后续迭代。

---

## 一、主状态（统一 6 态）

所有工作项类型（任务、里程碑、风险、阶段）在领域层统一为同一套状态枚举：

| 状态值 | 界面文案 | 含义摘要 |
|--------|----------|----------|
| `todo` | 待处理 | 尚未进入评审或执行，默认进度起点 |
| `review` | 项目经理评审中 | 提交项目经理评审；与自动化进度下限（如 5%）配合 |
| `reviewFailed` | 评审失败 | 评审未通过，进度回退 |
| `inProgress` | 进行中 | 评审通过后执行；参与员仅在此状态可更新进度 |
| `blocked` | 阻塞 | 执行期逾期未完成等导致的阻塞，或人工标记 |
| `done` | 已完成 | 闭环完成 |

历史数据中的旧状态（如 `planned`、`open`、`active` 等）在仓储映射层会**归并**到上述 6 态之一，避免列表出现多套状态文案。

---

## 二、阻塞与延期：展示分层

为避免「进行中 / 评审中」时出现易被误解的「逾期阻塞」文案，展示拆为两层：

1. **主状态 Badge**：只表达流程阶段（上表 6 态）。
2. **派生标签**：表达「为什么需要关注」或「历史上发生过什么」。

### 2.1 当前关注标签（未完成项）

典型规则：

- **评审超时**（`review` 且已超过 `dueDate`）：说明卡在项目经理评审环节，**不**把该情况统称「逾期阻塞」。
- **执行超期风险**（`inProgress`、已超 `dueDate`、尚未进入 `blocked`）：弱提示执行超期风险，**不叫**阻塞。
- **阻塞原因**（`blocked`）：
  - 优先展示 **依赖阻塞 / 依赖逾期**（一跳依赖，可带出项目名与工作项 `#id`）。
  - 其次 **自身逾期**。
  - 否则 **人工阻塞**（依赖 `blockedReason` 等字段）。
- **受依赖影响**（`inProgress` 且依赖方异常但未把本项置为 `blocked`）：提示上游影响。

### 2.2 历史痕迹标签（已完成等）

- **曾逾期**：如存在延期记录（如 `delayDays` / `delayStartedAt` 等）。
- **曾阻塞**：如完成后仍保留曾阻塞记录（如 `blockedStartedAt` 等）。

用于复盘「项目期间是否出现过逾期/阻塞」，而不再把已完成项当成当前阻塞。

### 2.3 实现位置

- 标签与判定逻辑：`lib/work-package-status.ts`（如 `getCurrentAttentionTags`、`getHistoryTags`、`getWorkPackageStatusInsights`）。

## 三、服务层与列表自动化

### 3.1 逾期与自动 `blocked`

- **仅当**工作项处于 **`inProgress`** 且已超过截止日期、进度未完成时，服务端自动逻辑会将状态置为 `blocked`（并写入相应阻塞说明/时间）。
- **`review` 超期**不自动改为 `blocked`，由展示层用「评审超时」等标签表达。

相关实现：`lib/services/work-package-workflow.ts` 中 `resolveAutomatedStatus` 等与 `updateWorkPackage` 流程。

### 3.2 读取快照时的自动态（若仍启用）

`applyAutomatedWorkPackageState`（`lib/work-package-status.ts`）应与上述口径一致：**只对 `inProgress` 逾期项**做与列表一致的自动阻塞展示，避免评审期被整体「刷成阻塞」。

快照拼装：`lib/repositories/workspace-repository.ts` 中对工作项列表的映射后处理。

## 四、「我的工作」与工作台 UI

### 4.1 「我的工作项」表格（`MyWorkbenchTable`）

- **状态列**：主状态 + 派生标签（当前关注 + 历史痕迹按规则展示）。
- **截止时间列**：展示 `dueDate`（ISO 日期 `YYYY-MM-DD`），无则 `—`。
- **依赖跨项目**：通过传入全量可见工作项与项目列表，派生标签可展示「因某项目 / #id 阻塞或逾期」。

页面数据：`app/(global)/my/page/page.tsx` 传入 `myWorkPackages` 与 `allWorkPackages`（快照全量工作项）等。

### 4.2 工作项详情

- 增加 **「阻塞 / 延期来源」** 小节，汇总当前关注与历史痕迹说明，便于团队负责人 / 项目经理复盘。

组件：`components/work-packages/WorkPackageDetailPane.tsx`；全屏详情页传入全量工作项与项目：`app/projects/[identifier]/work-packages/[id]/page.tsx`；项目内列表视图：`ProjectWorkPackagesView` + `app/projects/[identifier]/work-packages/page.tsx`。

## 五、需求项与角色（与本次状态展示相关部分）

- **团队负责人 / 项目经理 / 管理员**：创建或更新工作项时 **需求项至少 1 条**（服务端 `assertRequirementPolicy`）。
- **项目参与员**：创建子任务时需求项与附件可选；**仅能在 `inProgress` 更新进度**，不可改状态；分配与成员配置仅在负责人流程允许时开放（详见工作流与 `WorkPackageDetailPane` 权限分支）。
