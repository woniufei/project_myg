# 工作项需求项拆解与团队模块扩展

## 问题背景

项目管理平台原有工作项（WorkPackage）缺少**细分需求项（Requirements）**的录入与展示能力，导致子任务/里程碑创建时无法逐项罗列验收要求；同时缺少**团队（Team）**概念，无法按团队维度组织成员、设置负责人、关联项目。

## 根因分析

1. **Prisma schema 缺失模型**：没有 `WorkPackageRequirement` 和 `Team`/`TeamMembership` 模型。
2. **类型层缺失**：`lib/types.ts` 无对应 TypeScript 接口。
3. **API 层不传递需求项**：创建/更新工作项时不处理 `requirements` 字段。
4. **前端无输入与展示**：创建表单和详情面板均无需求项区域。
5. **权限矩阵未拆分**：RBAC 规则仅以单一矩阵定义，缺少团队长角色的支持。
6. **种子数据空白**：开发演示数据未包含需求项和团队示例。

## 解决方案

### 1. Prisma 建模（prisma/schema.prisma）

新增三个模型：
- **`WorkPackageRequirement`**：关联 `WorkPackage`，字段 `content`、`sortOrder`。
- **`Team`**：团队基本信息，字段 `name`、`description`、`leadId`。
- **`TeamMembership`**：用户与团队的多对多关系。

### 2. 类型扩展（lib/types.ts）

新增接口：
- `WorkPackageRequirement`（id、workPackageId、content、sortOrder）
- `Team` 和 `TeamMembership`
- `WorkPackage` 上新增 `requirements?: WorkPackageRequirement[]`

### 3. 映射函数（lib/repositories/workspace-mappers.ts）

新增：
- `StoredWorkPackageRequirement` 接口
- `mapWorkPackageRequirement()` 函数
- 在 `mapWorkPackage()` 中调用 `requirements?.map(mapWorkPackageRequirement)`
- `StoredTeam`、`StoredTeamMembership` 及对应映射函数

### 4. 权限矩阵拆分（lib/rbac.ts）

- 新增 `TEAM_LEAD` 角色到 `roles` 配置
- `TEAM_LEAD` 继承 `PROJECT_MANAGER` 的大部分权限（管理项目内工作项、审批），但无权管理项目成员
- 通过 `can()` 函数统一校验

### 5. 项目工作流（lib/services/project-workflow.ts）

- `TeamLead parentId` 校验：团队负责人创建子项目时，校验 `parentId` 是否在其管理的项目范围内

### 6. 工作项工作流（lib/services/work-package-workflow.ts）

- 创建/更新工作项时支持 `requirements` 数组
- 校验：`requirements[].content` 不能为空，长度不超过 500 字符

### 7. API 端点（app/api/work-packages/route.ts）

- POST/PATCH 请求体支持 `requirements?: { content: string; sortOrder?: number }[]`
- 在数据库中创建/更新关联的 `WorkPackageRequirement` 记录

### 8. 前端表单（components/projects/ProjectWorkPackageCreateForm.tsx）

- 新增「需求项」区块，支持动态增删需求项输入行
- 每条需求项包含 `content` 文本输入

### 9. 前端详情展示（components/work-packages/WorkPackageDetailPane.tsx）

- 在描述区域下方新增「需求项」Section
- 以无序列表展示 `requirements`，每条渲染 `content`

### 10. 种子数据（prisma/seed.mjs）

- 新增 9 条 `WorkPackageRequirement` 示例数据，关联到里程碑 #1、#10、#14
- 在 `main()` 中添加 `workPackageRequirement.deleteMany()` 和 `createMany()` 逻辑
